## 1. 仕様書駆動

- 網羅の台帳 = **規範セクション ID**。対象は
  [`../core/INSTRUCTION_ORBITSCORE_DSL.md`](../core/INSTRUCTION_ORBITSCORE_DSL.md)
  （単一信頼情報源・P.1 / PH.4 / MX.3 等）**および `specs-v2/` 配下の関連仕様**
  （SIGNAL_CHAIN_DSL_SPEC の SC.5 等 — DSL 表面を規定する仕様はすべて台帳に含める）
- fixture は**仕様セクション ID を名前に持つ最小 `.orbs`**（例 `P.3-range-sticky.orbs`）
- マニフェスト（構文 ID → fixture → 期待観測）による table-driven 実行

## 2. 漏れの担保 = 二重台帳の機械監査（CI ゲート）

「テストが存在しない構文」の検出を人間の注意力に頼らず、**集合差の機械計算**にする:

| 台帳 | 照合 | 検出するもの |
|---|---|---|
| 台帳1: 仕様書 | 仕様セクション ID ↔ fixture | 仕様にあるのにテストが無い構文 |
| 台帳2: 実装 | インタープリタ dispatch テーブルの全語彙 ↔ fixture | 実装にあるのにテストが無い構文 + 仕様との drift |

どちらも欠落を列挙して **CI を fail** させる。新セクション追加 = テスト追加が強制される。

**注意**: オフラインレンダリング（§3）は再現性の担保であって、漏れの担保ではない。

## 3. 2層構造

| 層 | 役割 | 実行 | 再現性 |
|---|---|---|---|
| **オフライン決定論層** | DSL 意味論の**網羅** | offline render（`verify_schedule_pcm` 系・デバイス不要） | 同一 `.orbs` → ビット一致 PCM。random は seed 固定 |
| **実機配線層** | 配線検証（**代表構文のみ**） | MCP 経由で実 OrbitStudio を駆動（evaluate / run_selection / get_log / capture WAV） | 許容幅つき意味論 assert（実機の位相ゆらぎを前提） |

## 4. アサーション — 構文ごとに意味のある観測（「鳴った」で済ませない）

- **音程系**（度数・root・mode・chord・voicing）: PCM / capture の**周波数解析**で実際の
  音高を assert（oracle synth は既知波形）
- **時間系**（polymeter・tempo・quantize・chop）: オンセット検出で相対タイミング
- **ルーティング系**（sum / aux / send / output / effect）: レベル比・チャンネル分離
- **エラー系**: `get_log` の文言
- マニフェスト各行に**観測タイプの申告を必須**とする。"smoke"（鳴っただけ）タイプは監査で警告

## 5. 無人実行

**テストの実行・判定・トリガーのどこにも人間を介在させない**（owner 確定。MCP と
ヘッドレス実行はこのために存在する）:

- 判定は解析（周波数・オンセット・レベル比・ログ照合）。「聴いて確認」を設計に含めない
- オフライン層は CI 常駐（PR ごと全構文）
- 実機層は実機マシンのスケジュール実行（有人トリガーは暫定であり解消対象）

## 6. 改ざん耐性

改ざん圧力の主体は人間だけでなく**エージェント自身も含む**。構造で防ぐ:

1. **期待値をマジックナンバーで書かない** — 仕様の式（IONIAN 表・root/octave 計算等）から
   期待値を導出する共有コードを1箇所に置き、fixture には意図（度数・root・oct）だけを書く。
   期待値の改ざんは仕様の式の改変として目立つ場所に強制移動される
2. **台帳監査**（§2）がケースの削除・スキップを集合差として検出する
3. **変異スイープの自動定期ジョブ化** — 代表変異（分岐反転・呼び出し回数・順序・引数差し替え）を
   機械適用し、**殺せない変異の増加 = assert の弱体化**を CI で検出する

## 7. テスト資産の機械生成（人間製成果物への依存禁止）

- fixture・期待値・state はすべて機械が生成する
- state 復元の E2E は実プラグインや人間保存の state を使わない。**oracle synth に意味のある
  state 実装**（例: state = 周波数オフセット）を持たせ、テストが自分で
  生成 → 復元 → 音高解析まで無人で閉じる（#543 の実装要件）

## 8. 学習サイトとの双方向監査

テストが正本・学習サイトは fixture の**消費者**（スニペットを埋め込む）:

```
仕様セクション ⟷ fixture       … カバレッジ監査（§2 台帳1）
E2E green の fixture → 学習ページ … 検証済み未記載の検出
学習ページの例 → green fixture   … 動かない例（嘘のドキュメント)の構造的排除
```
