### 0.2 🔴 新規起票の判断基準（運用規則・owner 決定 2026-09-03「地図を作り、issue をそれに合わせる」）

1. **起票前に、この地図の該当する節を探す。** 見出しの下に既存 issue があれば、そこに**コメントで足す**（新規起票しない）。
   `gh issue list` だけでは重複を防げなかった（2026-09-03 に #686→#218 / #680→#506+#522 の 2 件が同日に起きた）。
   **番号の検索ではなく、地図の見出しで探す。**
2. **地図に該当する節が無い作業は、まず地図を更新する PR を出す**（節を足す・依存を書く・正本 issue を決める）。
   issue は**その PR がマージされてから**起票し、本文の先頭に地図の節番号（例 `MAP §4.D`）を書く。
3. **`foundation` / `release-gate` / `must-fix` ラベルは地図から導く。** 地図の依存グラフ（§2）で他の節の前提になっているものが `foundation`、
   §3 の筋に乗っているものが `release-gate`、**演奏が壊れる／利用者が到達できないものが `must-fix`**。ラベルは地図の**写像**であって、独立に付けない。
4. **issue を閉じたら、同じ PR で地図の「現在地」欄を更新する**（WORK_LOG と同じ扱い）。
5. **Epic issue は作らない。** 地図の節が Epic の役割を持つ。既存 Epic（#292 / #546 / #517 / #413 / #187）は §5 の裁定に従う。
6. 地図の更新は docs-only PR。**日程・工数・可否は書かない**（書きたくなったら owner に渡す）。
