OrbitScore Signal Chain DSL Specification v1

Status: 正本（specs-v2）/ 2026-07-18 制定 / 受け皿 issue: #506 / 決定ログ: DESIGN_DISCUSSION_RECORD §15（決定 #64–#77）/ 実装: #495 言語サービスと同時設計（本仕様の制定時点では未実装）

位置づけ: 本仕様は effect() / instrument() / 文字列ルーティングの表記と名前空間の刷新である。 エンジン側のミキサーグラフ実体（MX 仕様のバス・ルーティング・LinkAudio ゲート）は不変。 audio シーケンスの play() 意味論は一切変更しない（運用規則5）。 既存の文字列形 API はすべて互換として存置する（§SC.8）。

SC.0 全体像

// ── ミキサー空間を init して派生させる
var mix    = init global.mixer        // 卓そのもの
var master = mix.output(1, 2)         // 物理アウト 1-2 = メイン
var subout = mix.output(3, 4)         // 物理アウト 3-4（マルチアウト）
var drums  = mix.sum                  // グループバス
var verb   = mix.aux                  // センドリターン
var duck   = mix.aux                  // サイドチェーン搬送も aux（役割は受け手が決める）

// ── リターン側のチェーン（バスもシーケンスと同じ書式）
verb.HogeReverb(size: 0.8).master

// ── トラック
kick.audioPath("kick.wav").chop(16).play(1, 5, 9, 13)
    .CLAPTestEffect(mix: 0.5)
    .HogeComp(threshold: -18, sidechain: duck)
    .verb(0.3)                        // aux 名 → send（位置 = プリ/ポスト）
    .FugaEQ(low: 2)
    .drums                            // sum 名 → 本流の出力先（宣言層・括弧なし）

bass.audioPath("bass.wav").play(1, 9).duck(1.0).drums
drums.GlueComp(ratio: 2).master
lead.Serum(preset: "Pluck 01").TALReverb4(size: 0.6).subout

SC.1 二層意味論 — 宣言は集合・信号は列

層属するもの順序の意味
宣言層 audioPath / chop / play / gain / pan / 出力先ノード名（括弧なし）/ instrument 役のプラグイン呼び出し / ミキサー宣言 可換。どこに書いても同じ。同一項目の再宣言は後勝ち。
信号層 effect 役のプラグイン呼び出し / send（aux 名メソッドを含む） この層内の相対順序だけが接続順になる。宣言層の文がどこに挟まっても影響しない。
規範: (1) チェーン1本と行分割呼び出しは完全等価（同一の評価列であるため）。 (2) トポロジーは構造で固定される: パターン(play) → instrument → エフェクト列 → 出力先。 利用者が順序で制御できるのはエフェクト列の中身と send の位置のみ。 (3) play() の意味論は本仕様の影響を受けない。

SC.2 ミキサー宣言

SC.2.1 mixer 空間とノード派生

var mix = init global.mixer
派生宣言意味備考
var master = mix.output(1, 2)物理出力チャンネル対（出力エンドポイント）複数宣言でマルチアウト。デバイス ch 数超過は起動/デバイス切替時に警告（#484 D4 と接続）
var drums = mix.sumグループバス（合流点）MX.2 の sum と同一実体
var verb = mix.auxセンド用バスMX.4 の aux と同一実体。サイドチェーン搬送も aux で行う（汎用 bus 型は設けない — 決定 #74）
規範: (1) global.mixer は暗黙に1つ存在し、init は同一空間への名前付きハンドル取得である（卓は1枚）。 (2) 宣言された識別子は名前空間を確保し、以後 (a) send のバス名メソッド (b) 出力先指定・sidechain: 等の引数、として使える。 (3) 解決優先順位: 宣言済みミキサー名 > プラグインカタログ名。衝突時は言語サービスが警告する。 (4) send / 出力先が作るグラフは DAG でなければならない。循環は評価時に明示エラー。 (5) ミキサー宣言の無いファイルは暗黙 master(1,2) を持つ（現行互換・素朴な1ファイル経路の保護 — 決定 #75）。

SC.2.2 import による卓の共有と拡張

// mod/mixer.orbs — 定番の卓
var mix    = init global.mixer
var master = mix.output(1, 2)
var verb   = mix.aux
verb.HogeReverb(size: 0.8).master

// song.orbs — 曲側
import { mix, master, verb } from "./mod/mixer.orbs"
import * from "./mod/mixer.orbs"              // フラット star import も可（決定 #72）
var tapeDelay = mix.aux                       // 曲固有の追加派生
規範: (1) import 構文は既存 IM.1〜IM.6 のまま（新構文なし）。加えてフラットな import * from を許す。 (2) 実体は import 時の評価で共有空間に生まれる。名前は列挙（または *）でスコープに入れた分だけ見える。 (3) { mix } のみの import でも mix.aux 等での拡張は可能（aux はメソッドであるため）。

SC.3 プラグイン呼び出し（メソッド形）

SC.3.1 形

receiver.PluginName(param: value, ...)     // receiver = シーケンス or バス
規範: (1) パーサは未知メソッド名を受理し、解釈時に「宣言済みミキサー名 → プラグインカタログ」の順で解決する（文法は静的・語彙は動的）。 (2) 引数はすべて名前付き。パラメータ名はプラグインの parameter enumeration（CLAP/VST3 API）に由来する。() はデフォルト値のまま挿す。 (3) effect 役の呼び出しは信号層、instrument 役の呼び出しは宣言層に属する（SC.1）。 (4) instrument は1シーケンスに1つ・後勝ち（差し替え）。トポロジー上の位置は構造固定であり記述順と無関係。

SC.3.2 名前の正規化と衝突

規範: (1) 正規化: カタログ名から英数字のみを連結する（"TAL Reverb 4" → TALReverb4）。先頭が数字の場合は _ を前置。 (2) 正規化で表現できない名前（非英数字のみ等）はメソッド形の対象外とし、逃げ道（effect("名前")・SC.8）を使う。 (3) format 衝突（同名が CLAP と VST3 双方に存在）は予約引数 format: で解消する。未指定は CLAP 優先（PC.2 と同一規則）。

SC.3.3 予約引数

引数意味備考
format:"clap" | "vst3"（将来 "au"）同名衝突の解消
vendor:ベンダー名同名別ベンダーの解消
sidechain:宣言済み aux をサイドチェーン入力へ接続識別子を渡す。M2 multi-bus（#409）実装まで明示エラー（silent 無視禁止）
outs:マルチアウト instrument のポート→バス割り当てouts: { "kick": bdBus }。#408 実装まで明示エラー
preset:プリセット適用対応 format のみ
enabled:バイパス（状態保持）kick.HogeComp(enabled: false)
規範: プラグイン側に同名の実パラメータが存在する場合は予約語が勝ち、警告を出す。実パラメータへは enumeration の ID 指定で到達可能にする。

SC.4 ルーティング — ノードの型がメソッドの意味を決める

.verb(0.3)      // aux 名（量を取る）        → send（信号層・位置が意味を持つ）
.drums          // sum 名（括弧なし）        → 本流の出力先（宣言層・後勝ち）
.master         // output 名（括弧なし）     → 本流の出力先（宣言層・後勝ち）
規範（決定 #77）: (1) aux 名メソッド = send。send(識別子, amount: x, enabled: b) の糖衣であり、send が唯一の分岐 primitive。第2位置引数は amount: の省略記法。 (2) sum / output 名メソッド（括弧なし）= 本流の出力先指定。宣言層に属し後勝ち。output(識別子) の関数形は互換として残す。 (3) send はチェーン上のその位置の信号をタップする: エフェクトの前 = プリ、後 = ポスト。複数可。send は分岐であり本流を変えない。 (4) 送り先の役割は受け手が決める: 同じ aux を、リバーブのチェーンが受ければリターン、他プラグインの sidechain: が受ければサイドチェーンになる。送る側は区別を持たない。 (5) バス名以外の目的別動詞（aux() 別名等）は設けない。動的語彙は「プラグイン名」「宣言済みミキサー名」の2種に限る。

SC.5 ライブコーディング意味論

規範: (1) インスタンス同一性 = (レシーバ, 正規化名, レシーバ内の同名出現順)。 (2) 再評価 = パラメータ更新: 同一インスタンスへの再呼び出しは、音を止めずに指定パラメータのみを更新する（二重挿入しない）。これがライブのパラメータ操作であり、#460 オートメーションの静的端点。 (3) 新しい名前の評価 = チェーン末尾に追加。 (4) ブロック再評価 = 置き換え（決定 #73）: 評価単位は空行区切りブロック（現行 REPL の確定単位と同一）。ブロックを再評価すると、そのブロックに現れた構成で当該レシーバのチェーンを置き換え、消えたプラグインはアンロードする。1行単独の評価は更新/追加のみで削除しない。 (5) 帰結としてコメントアウトがバイパスの最速 UI になる: ブロック内の行を // で殺して再評価 → アンロード、コメントを外して再評価 → 復帰。 (6) 明示削除は remove("名前")（出現順指定 remove("名前", n)）。enabled: false（状態保持バイパス）と使い分ける。 (7) ミキサー宣言の再評価は冪等（後勝ち）。使用中バスの削除は「参照が残っている」エラー。

SC.6 エディタ支援（言語サービス要件）

  • kick. 直後: 通常メソッド + 宣言済みバス名 + レシーバに挿せる役割のプラグイン名を候補に出す。kick.e と打てばエフェクト名が、pitch シーケンスで .i と打てば instrument 名が絞り込まれる（名前自体が候補であるため）。
  • プラグイン名確定後の ( でパラメータ名補完（enumeration から。範囲・単位を detail に）。予約引数も同列に出す。
  • 出力先・sidechain: の位置では宣言済みミキサー名のみを出す（文脈限定）。
  • 実装段階: 第1段 = カタログ + regex 文脈で名前系のみ。第2段 = #495 言語サービスでシンボルテーブル・レシーバ種別判定・パラメータ補完。

SC.8 互換と移行

規範: (1) effect("名前") / instrument("名前") / 文字列バス形（global.sum("drums")・output("drums")）はすべて存置する（後方互換 + 素朴経路の恒久保護 + 正規化不能名の逃げ道）。 (2) 文字列形で宣言された名前もメソッド化の対象になる。 (3) docs / learning site はチェーン形を正、文字列形を代替として記載する。
